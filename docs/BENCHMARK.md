> 目的：用工作台跑一次完整的多人协作任务，记录耗时与 token，作为后续优化对照。
> 任务：3 个成员协作做一个零依赖 Canvas 射击游戏（GK Shooter），验收 90 条断言。

## 成本结构

1. **Lead 占 68%**，且 99.8% 是 cacheRead——因为 Lead 会话在测试前已经很长。换全新会话跑同类任务，Lead 成本预计能到 1/3～1/2。
2. **执行成员倍数是 17–40×**，远低于 Lead；契约先行 + 短会话有效。
3. **瓶颈在「实现完成后才开始验收」**：core（181s）与 presentation（268s）并行，QA（235s）串行在最后。

## 下一轮复跑目标

- 用全新会话（降低 Lead cacheRead）
- QA harness 前移：实现期间就按契约写骨架
- 给表现层更硬的视觉规范，减少自迭代
- 目标：墙钟 ≤8 min、计量 token ≤15M、重读 ≤45×

复跑时用工作台的「本次任务成本」面板或 `GET /agent-cockpit/taskcost?lead=<id>` 取同口径数据。

## 口径

- 增量：只统计开始时间之后的事件（`assistant/message.usage` 累加），与工作台「本次任务成本」同源。
- 计量 token = input + output + cacheRead。
- 重读倍数 = cacheRead / (input + output)。
- 墙钟含需求理解、写契约、spawn/收消息、集成、验收、截图、报告。

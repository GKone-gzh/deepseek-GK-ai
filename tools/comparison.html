不调用 AI 协助 vs 调用 AI 协助

GK协助工作台 · 把「多 Agent 协作」变成可观察、可控制、可算成本的会话能力
不调用协助 · 单 Agent

一个 Agent 从头做到尾

所有步骤串行，上下文只进不出；适合需求明确、强顺序依赖的小任务。

1串行执行：读 → 改 → 测 → 汇报都在同一条上下文里
2上下文线性增长：越到后面越贵，cacheRead 持续放大
3没有分工：探索、实现、验收都由同一个 Agent 承担
4优势：不需要协调、不会互相等、修改范围小
调用协助 · 多 Agent

Lead 切任务，成员并行交付

契约先行、写范围不重叠、共享任务板；协作模式默认「先询问」，预算到线会真的中断成员。

1并行分工：核心 / 表现 / 验收可以同时推进
2关键路径可见：最长链、阻塞任务、写范围冲突一眼看到
3成本可见：本次任务增量、每步输出、重读倍数
4可控：协作询问门禁、预算熔断、空闲成员归档
10.2 min实测墙钟（3 成员协作做射击游戏）
120 步实测总步数
22.77M实测计量 token
90/90验收断言全部通过

怎么选

单 Agent小改动、强顺序依赖、需求还没定清楚、只需一份产出
多 Agent 协作多模块并行、大范围只读调研、一次要多份独立产出
拿不准用「询问」模式：Agent 判断需要协作时先问你，同意后才组队
